# 轨道效果

“效果”是附加到现有轨道的处理链。背景、图片、视频、唱片、歌词、频谱、播放器装饰、曲目信息、文字、粒子和光影氛围均可分别添加全部画面效果。主音轨 A1 支持“淡入淡出”，用于音乐音量渐变。每条轨道最多保存 8 个效果实例，可以重复添加同一种效果。

## 添加与编辑

1. 在画布、图层列表或时间线中选中需要处理的组件，打开左侧“效果”。可按分类筛选，也可搜索名称或说明。
2. 点击效果卡片，将它添加到当前选中的画面组件；也可以把效果卡片拖到目标画面轨道。目标组件锁定时，先解锁再添加。
3. 在右侧“效果”页查看当前组件的效果栈，调整每个效果的强度和专用参数。效果按列表顺序依次作用；改变顺序会改变叠加结果，例如先调色再加颗粒，与先加颗粒再调色的结果不同。
4. 各效果可独立开关、上移、下移、重置或删除。重置恢复该类型的默认参数、100% 强度及启用状态；关闭或将强度调为 0 可以暂时旁路该效果。
5. 使用复制全部效果与粘贴操作，将整套效果追加到另一个组件现有的效果栈末尾。粘贴不会替换目标已有的效果，追加后总数仍受 8 个上限约束。

单个效果右侧也有复制按钮。主音轨不接收画面处理效果，包含不兼容类型的整栈粘贴会完整拒绝，可单独复制其中的淡入淡出。点击时间线 A1 或它的 FX 标记即可编辑音频效果。

新增、删除、排序、预设和参数修改支持撤销、重做。滑块的一次连续拖动作为一次修改。效果设置随 `.visiki.json` 工程保存；复制组件时一并复制其效果，各实例之后可独立编辑。

## 效果种类

| 效果 | 参数 | 适用方式 |
| --- | --- | --- |
| 基础调色 | 曝光、亮度、对比度、饱和度、色温、色调、高光、阴影 | 单独校正背景或视频，也可调整文字、封面和装饰的颜色 |
| 胶片质感 | 颗粒强度、颗粒大小、褪色、暗角、胶片闪烁、划痕、变化速度、随机种子 | 为已有画面增加颗粒和旧胶片气氛 |
| RGB 分离 | 分离距离、分离方向、分离波动、变化速度、随机种子 | 为轮廓增加红蓝错位，适合标题和电子风格画面 |
| 数字故障 | 故障幅度、切片高度、触发频率、故障色偏、变化速度、随机种子 | 生成间歇性的切片错位和色彩干扰 |
| CRT 显示器 | 扫描线强度、扫描线间距、屏幕暗角、屏幕曲率、屏幕闪烁、变化速度、随机种子 | 制作显示器扫描线和曲面屏幕观感 |
| 音乐呼吸／频段联动 | 频段、灵敏度、阈值、响应、回落、缩放、亮度、透明度变化 | 使用真实音乐能量驱动单个画面组件 |
| 淡入淡出 | 独立淡入／淡出时长、样式、曲线、移动距离、歌词范围 | 画面渐显与出入场；A1 音乐音量渐变 |

基础调色提供“还原原色”“暖调柔光”“清冷蓝调”“黑白影调”“低饱和褪色”五个预设。预设用于快速填入调色参数，应用后仍可逐项修改。“还原原色”的全部参数中性，不会额外改变画面；同一栈中的其他效果继续生效。

曝光范围为 −2 至 +2 EV；饱和度为 0 时得到黑白画面。RGB 分离距离最高为 40 px；故障的触发频率范围为每秒 0.1–30 次。含“变化速度”的效果可调为 0–3 倍，速度 0 保持同一动态相位。像素单位以工程画面坐标计，不随预览面板缩放比例改变。

胶片、故障等动态纹理由随机种子和组件局部时间共同确定，局部时间为工程当前时间减去组件起点。移动组件后，纹理跟随新的起点播放；视频分割或裁切起点时保留累计效果时间，避免动态纹理在切口重新开始。音乐联动使用歌曲全局时间，淡入淡出使用组件或歌词区间，均可任意跳转，无需从头播放。详细参数及兼容规则见 [音乐联动与通用过渡](music-effects.md)。

## 与图层的关系

效果只处理所附加组件已经绘制的像素，不会把其他轨道一起调色或叠加颗粒。透明背景继续透明，胶片或 CRT 不会给文字、粒子等组件额外增加整幅底色。组件原有的不透明度、出现区间、显隐、旋转、字体、自发光、歌词透视及出入场动画继续参与绘制。

光影氛围组件仍保留原有的正常、滤色和添加混合方式：先对该组件自身的光影像素应用效果，再按其混合方式与下方画面叠加。若希望为多个组件设置相同观感，可复制整套效果到其他组件。本版尚未加入一次处理多条轨道的全局调整层。

## 实现方式研究与选型

Adobe 对效果类型的说明区分固定效果与可添加的标准效果，并说明标准效果可以改变应用顺序。这里参考的是“效果附着到片段、按栈顺序处理”的编辑方式，效果代码由本项目实现，不加载 Adobe 或剪映插件。参见 [Adobe：Types of effects](https://helpx.adobe.com/ie/premiere/desktop/add-video-effects/types-of-effects/types-of-effects.html)。

本项目选择以下集成方式：

- **数据独立于组件参数**：图层可选保存 `effects` 数组，主音轨保存工程级 `audioEffects`；每项包含 `id`、`type`、`enabled`、`strength`、`params`。工程导入校验类型、目标兼容性、数量、实例标识和参数范围。没有旧过渡的工程保持原有绘制流程；旧内置过渡按兼容规则迁入淡入淡出效果。
- **先隔离组件，再处理像素**：复用工程画布尺寸的透明 HTML Canvas，仅绘制当前组件；不以编辑选框作为裁切边界，避免给歌词首尾行、透视字面、阴影和发光增加选框裁切。HTML Canvas 在绘制文字时挂载到文档，保留现有字体合成策略。
- **透明度只作用一次**：隔离绘制保留组件原有透明度，效果完成后以完整合成透明度放回主画布。光影氛围的滤色或添加混合留到最后合成，避免对透明中间层混合后丢失与下方画面的交互。
- **有序 GPU 处理与兼容回退**：连续像素效果优先使用 WebGL 着色器及交替复用纹理、帧缓冲；不可用时使用 CPU 像素处理。遇到音乐联动或过渡时，先完成前一组像素处理，再以一个复用缓冲合成变换，随后继续后续效果，保留栈顺序。当前时刻没有启用且实际生效的效果时直接走旧渲染路径。
- **预览与导出共用入口**：效果接入现有场景渲染函数，由相同参数、种子与时间生成画面；音乐联动使用离线包络和全局歌曲时间。渲染缓冲有界复用，不按播放帧数持续积累。

WebGL 文档提示纹理和帧缓冲的内存开销，以及同步像素读取可能造成的等待；这支持了本项目复用资源、让效果链尽量留在 GPU 的选择，并不意味着官方要求使用某种编辑器架构。参见 [MDN：WebGL best practices](https://developer.mozilla.org/en-US/docs/Web/API/WebGL_API/WebGL_best_practices)。

Canvas 2D 的 `filter` 可以提供模糊、亮度等简单处理，但兼容性有限，也不能独立表达本轮全部像素效果。因此不依靠预览元素的 CSS 滤镜生成最终视频。参见 [MDN：CanvasRenderingContext2D.filter](https://developer.mozilla.org/en-US/docs/Web/API/CanvasRenderingContext2D/filter)。

本轮尚不包含效果关键帧或全局调整层。多条轨道叠加多个动态像素效果会增加渲染开销，可在编辑时关闭暂时不需要的效果，输出前再启用。
